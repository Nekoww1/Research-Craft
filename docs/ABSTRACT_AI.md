# Abstract：人与 AI 共用的知识样板

2026-10-21。用户认可先把 Abstract 做成可调用样板，用真实任务比较后再决定扩展。当前只覆盖摘要；其他写作页仍是教学正文，没有自动升级为相同规范。

## 怎样使用

最新任务分工：用户明确AI区可保留结构化展示，本轮仅细分任务与选材联动。可直接进入[AI任务区](http://127.0.0.1:4173/ai/abstract/index.html#tasks)，切换后查看对应输入、交付物、依赖概念、规则与案例。正式教学仍在 [Abstract章节](../writing/abstract.html)，不由本页替换。

用户反馈规范页过于结构化、难以理解后，当前[阅读页](http://127.0.0.1:4173/ai/abstract/index.html)默认从改稿与解释开始，不显示概念／案例编号；操作字段放进“给AI用”。源编号留在数据和链接中，来源说明仍在相关内容旁边。已审计的开头对照直接从教学源提取，避免手工维护两份例文。

需要AI协助时，展开“给AI用”或从页首链接进入，再选择起草、修改或审查。预览直接显示实际选材；需要补充指导时勾选对应条件，预览、复制和下载同时变化。每个任务保留自己的选择，切换不会串用另一个任务的案例。下载／复制后另附填写好的[研究材料模板](../ai/abstract/input.example.json)。普通对话模型可直接读取这些文件；有仓库访问权限的 agent 可以从 [AI 入口](../ai/abstract/README.md)按任务读取，不必加载整个网站。

输入须说明完成状态、贡献类型、目标篇幅与范围，给出带编号及依据位置的当前事实。修改／审查还需要草稿；可选附标题、引言、结论等相关章节。未提供跨节材料时只能报告未检查，不能声称一致。完成稿缺少关键证据时先补材料；计划稿不得补造已完成结果。

也可以在仓库根目录组装一份完整输入：

```powershell
python -X utf8 scripts/build_abstract_pack.py --task revise --input .local/my-research.json --output .local/abstract-prompt.md
```

需要补方法动作时加 `--include-rule R-ABS-03`；可重复此参数补选本任务允许的指导。该命令只组装文本，不调用模型。起草用 `draft`，审查用 `audit`。模板中的空事实不能直接运行；文件放在哪里不改变事实的可信度。CLI只检查必要字段与缺失信息，不验证输入事实是否真实。

| 任务 | 默认选材与职责 | 需要时补选 |
| --- | --- | --- |
| 起草 | 共通5条＋R02／03／06，共8条；从事实组织完整信息、方法动作与合适形式；看Forest结构案例 | R07：已有信息骨架，还需语言／篇幅精修 |
| 修改 | 共通5条＋R07，共6条；定位错误与表达负担，保留正确内容，给改稿和修改依据；看A集合结果改写 | R02：重写开头；R03：补关键动作；R06：调整贡献类型／格式组织 |
| 审查 | 共通5条＋R02／03，共7条；核查支持与信息连接，给定位、优先级、依据和动作，默认不重写全文；看缺结果案例 | R06：格式／形式核对；R07：明确要求语言详审 |

共通5条为R01／04／05／08／09，覆盖当前事实、比较条件、研究状态、事实映射与统计措辞。它们仍按各自条件执行，不要求每项研究进行统计检验。页面的“全部规则备查”是完整库，不等于当前任务全部载入。补选由使用者主动决定，本版没有自动诊断草稿后选择规则；默认任务包不会包含未选模块的全部说明。

网页预先生成14种有限组合，复制与自定义下载取自同一生成器，避免浏览器重新拼写另一套规则。无脚本时三任务及补选参考均可阅读，下载为默认包，选择控件不显示；完整指导仍在 `knowledge.md`。此为静态交付方式，不调用模型，也不上传当前研究材料。

## 共用的是什么

唯一知识底稿为 [knowledge/writing/abstract.json](../knowledge/writing/abstract.json)。它保存4个概念、9条规则、3个标注案例及3种任务的选择关系。连续教学正文仍在 `content/writing/abstract.html`，不从规则自动拼成一章；生成页提供默认收起的对应规则链接。本轮修改了任务分工与三份默认材料，没有改规则含义、完整知识Markdown、研究事实模板或六次冻结对照。旧模型结果对应旧选材，不能据其宣布本轮质量已提升。

| 记录 | 固定字段与用途 |
| --- | --- |
| 原文依据 `E-ABS-*` | 来源编号、作者、页码／小节、实际支持的主张、原文身份、语境与阅读范围 |
| 概念 `C-ABS-*` | 定义、作用、依赖概念、来源支持关系、对应教学位置 |
| 规则 `R-ABS-*` | 适用条件、所需事实、动作、信息缺失时的处理、完成检查、采用身份、概念与来源依据 |
| 案例 `EX-ABS-*` | 真实释义或教学构造的身份、修改／处理、分段标注、关联规则、事实使用边界 |
| 共通规则 `common_rule_ids` | 所有任务共享的核对，不能通过补选控件移除 |
| 任务 `draft/revise/audit` | 目标、所需输入、执行步骤、交付物、重点规则 `rule_ids`、可补选规则与条件 `optional_rules`、概念／案例编号 |

编号用于稳定引用，不表示阅读次序或质量等级。修改已有单元保留编号；确有不同概念才新增，不能仅为分句增加规则。规则的 `project_requirement`、`recommendation`、`conditional` 分别表示本站事实约束、通常建议和有条件采用，不把作者经验全部升级成硬性要求。

每一项 `basis` 指明证据编号、关系与支持范围。关系区分原文转述、不同讲法对照、据此推演、编辑操作化、案例分析和教学设计。比如 Jones p.24 原本谈引言主张与正文证据，把它用于摘要逐句事实映射是本站操作化，不能归给作者一个原文不存在的 AI 协议。编写前决策见 [来源先行记录](ABSTRACT_AI_AUDIT.md)。

## 两条依据怎样分开

写作依据支持“为什么这样组织与表达”，当前研究事实支持“本论文能说什么”。事实编号 `F-*` 与规范编号 `R-*` 分开；写作教程的引文不自动变成论文研究引文。全部案例均设 `may_supply_project_facts: false`，包括真实 Forest Reranking 释义。使用者研究该案例时仍应明确提供其当前事实，不能靠示例默默补齐。

任务先加载有关规则，再递归补全其概念依赖，每个任务只选一个案例。起草重信息职责与事实映射，修改重诊断—改动—依据，审查重可定位问题、事实支持和修订动作。只要求简短可核对的说明，不要求内部思维过程，也不将出现规则编号当作写作质量证据。

刘洋的四项信息、Jones 的会议论文四句建议与 Mensh／Kording 的背景—内容—结论保留各自语境。规则帮助按材料选择，不能把它们合成所有作者共同制定的句型。

## 维护与验证

先读原文并记录支持判断，再改知识 JSON。若连续教学也改变，分别修改教学源与正文审计；只改知识单元不会自动证明原正文已同步语义。运行：

```powershell
python -X utf8 scripts/build_writing.py
python -X utf8 -m unittest discover -s tests -p test_abstract_pack.py -v
python -X utf8 scripts/build_writing.py --check
python -X utf8 scripts/verify_site.py
```

构建同步 `ai/abstract/` 的7份文件、摘要页的入口与规则链接。测试发现缺引用、任务选材错误、缺关键事实仍起草、生成不同步等失败；不自动判断原文是否蕴含规则。网页交互用 `scripts/abstract_ai_check.cjs` 检查，运行环境见 [验证记录](VALIDATION.md)。

实际对照保留[固定输入、六次独立答复与分析](../evals/abstract/run-2026-10-21/REPORT.md)。本轮确认输入更短、产物可追溯，但没有证实质量优于整章输入。尚未安装为平台专属 Skill，没有模型 API、自动检索服务或投稿能力；当前 Markdown 接口足以先验证工作流。后续优先用自己的真实论文和不同贡献类型检验，再决定扩到 Introduction、Method 或 Results。
