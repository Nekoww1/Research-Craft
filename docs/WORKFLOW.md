# 收集、归纳与编写流程

日期：2026-10-20。用户认可本流程的整体方向，并要求交接到新 session 后直接开展工作。这里给出实施起点，具体材料、章节与界面按实际内容细化。

## 1. 本轮目标

把现有线索整理成可追溯的材料基础，形成一批能用于教学的概念与案例，并实现可以本地浏览、包含真实内容的首版前端。

收集、阅读和综合由代理承担。用户可通过实际使用、内容反馈和自身研究经历参与修订，不以用户先精读全部材料为启动条件。

首轮不以来源数量或页面数量衡量完成度。需要贯通材料理解、教学编写与界面呈现，并为后续扩展保留清楚的来源和进度记录。

## 2. 收集：先核实归并，再补实际缺口

从 `SOURCES.md` 的 19 条线索开始，核对原始材料身份，区分原文、报告整理、转录、镜像、转载和资料目录，归并同一材料的不同入口。

首轮可选择约 6—8 份互补的实质材料作为工作预算，数量不构成硬指标。优先处理用户重视或提供的刘洋、Omar、彭思达材料，再结合 Alon、陶哲轩、Simon Peyton Jones、Lipton／Steinhardt 等补充具体缺口。

彭老师仓库的 README 是入口，不能替代实质文章或课件。Notion 仍无法获取时记录缺口，并继续其他独立工作；不依据标题补造其观点。

同时收集两类内容：

- 方法论材料：作者提出的观点、理由、方法和边界。
- 教学案例材料：沿上述文章的引用，追到实际论文、项目、图表或文本，用于具体讲解。

新增来源需要说明它补上什么内容。判断是否纳入时，关注可核实的具体方法、案例、适用范围及互补性。作者声望不能替代对材料内容的判断。

## 3. 阅读：先理解整篇，再提取教学素材

每份核心材料先形成阅读记录：作者面向谁，写作背景是什么，整篇论点与顺序是什么，实际读到哪些部分，哪些仍然缺失。

从中提取观点或方法时，保留必要上下文：

| 项目 | 记录内容 |
| --- | --- |
| 核心观点 | 作者具体主张什么 |
| 理由 | 为什么这样主张 |
| 案例或依据 | 用什么例子、分析或经验支撑 |
| 适用条件 | 面向什么研究、资源与阶段 |
| 行动含义 | 读者可以据此怎样做 |
| 原文定位 | 页码、小节、段落或其他可核对位置 |
| 编辑备注 | 我们的解释、疑问和待核实之处 |

不必把所有项目硬填成统一表格；这是一组应保留的信息。没有提供的依据或条件应标明未知，不代作者补写。

## 4. 分类：分别记录内容主题和教学用途

一份材料可以关联多个主题，分类随着阅读调整。初步目录用于检查覆盖范围，不能迫使原文进入预设框架。

- 内容主题示例：问题价值、可行性、领域视野、证据与解释、引言、长期方向。
- 教学用途示例：概念解释、真实案例、观点对照、操作方法、写作模板、边界说明。

分类后应能辨认某个主题拥有的是抽象建议、充分案例还是具体操作材料，进而决定补什么来源、采用什么讲法。

## 5. 归纳：建立关系，再形成编辑解释

比较观点时，分别识别相近主张、互补环节、条件差异、实质分歧和尚未覆盖的内容。保留来源身份，不把反复转载当作多个独立意见。

例如，Omar 的长期项目、Alon 的问题可行性与阶段差异、陶哲轩对过早执着单一大问题的提醒，可以共同进入长期方向的讨论。怎样将它们组织成教学解释属于编辑综合，需要明确身份并由具体案例补充。

概念整理应说明其含义、与其他概念的关系、适用条件、原始依据和可用案例。仅提炼一句原则不代表教学内容已完成。

## 6. 编写：依据概念顺序与模块特点讲完整

先确定需要理解的概念及其前置关系，再组织连续正文、案例与行动指导。

- 研究 taste：复盘可核实的选择、依据、不确定性和后续变化，避免将成功结果反写成作者当时必然掌握的判断。
- 写作：结合原文批注、结构分析、修改对照、模板和适用条件；自行改写的文本要明确身份。
- 实验与论证：解释主张、验证方式、结果与解释如何对应。
- 其他模块：依实际材料选择教学构造，提供明确行动指导。

正文完成后再酌情设计简短引入问题，并选择合适图解与交互。引入问题不决定章节内容；正文应支持跳过问题后的完整阅读。

需要重要概念或案例但材料不足时，回到收集阶段定向补充。

## 7. 前端：用真实小节检验呈现方式

当前工作方向是一部可连续阅读、可按需查阅的科研成长书。首页可先采用简短导言和全书目录；正文保持连贯，并在相关位置呈现来源、案例和具体做法。

先选择一段研究 taste 内容和一段写作内容进行完整教学编写与呈现，具体主题可按材料调整。统一阅读与导航习惯，同时让不同模块保留自己的教学结构。

技术栈选择最简单、适合当前内容并便于静态托管的实现，说明主要理由后直接推进。GitHub Pages 是候选发布方式，启用发布尚未包含在当前已执行状态中。

不要让首版只有目录、空页面或尚未经过来源核对的演示文案。来源研究、教学内容和前端可以分批迭代，首版完成后仍需继续扩展全书。

## 8. 首轮成果与完成判断

首轮留下：

1. 可追溯的来源与阅读记录，说明实际阅读范围和访问缺口。
2. 概念关系与案例素材，保留适用条件、分歧和编辑综合。
3. 包含连贯讲解、具体指导与就近引用的教学小节。
4. 可本地浏览的前端，体现案例教学和写作对照的不同构造。
5. 与实现相称的构建及浏览验证记录，并更新交接状态、提交和同步 Git。

选定内容能够被讲清、能提供具体做法并说明边界时，应进入编写和展示。新增来源主要重复已有内容时，不为追求数量继续扩张资料池。

以上是首轮可审查成果，不代表整个科研方法论项目已经完成。后续依据内容缺口与使用反馈继续扩展。

## 9. 文件与持续记录

先使用仓库内可版本管理的普通文件保存阅读记录、概念整理和章节内容，具体目录由实现时选定。当前阶段无需为此先建立数据库。

更新来源的真实阅读状态；记录重要的新决定、缺口、验证结果与后续任务；让下一 session 可以从仓库接续。
